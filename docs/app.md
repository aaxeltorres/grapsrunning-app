# App modules: theme, components, screens, navigation, hooks, storage, tasks, utils

Moved verbatim from CLAUDE.md. See also docs/coach.md and docs/run.md.

- `src/theme`: design tokens (colors, typography, spacing). Use them; do not hardcode values.
- `src/components`: reusable UI components. `Button` has one primary variant, the brand blue (`colors.iosBlue`, the blue of Home's Start run; `accent` is an older name for the same style), plus `secondary` (gray), `outline` and the `runPause` / `runFinish` variants of the dark run screens. White on that blue is 4.0:1 (fine for large text and controls, under 4.5:1 for normal text; the same pair Apple's system buttons use).
- `src/screens`: app screens
- `src/navigation`: navigation and route types
- `src/hooks`: shared hooks, including run tracking and the chat engine (`useChatReveal`, which hands out stable `displayItems`; `OnboardingChat` memoizes each message group and follows the conversation with one post-layout scroll per new entry, never while the user is dragging or has scrolled up)
- `src/storage`: persistence behind small modules with get / save / clear, backed by AsyncStorage for now. `profileStorage` keeps the runner profile, `planStorage` the training plan (`update(change)` is a read-modify-write used to record a finished run), `intervalStorage` the last Intervals setup (normalized to the current limits when read), `runHistoryStorage` the run history (`loadRuns` newest first, `saveRun` upserting by id, `getRun`, `deleteRun`; a missing or corrupt store reads as an empty list; writes are queued; only runs that pass `isRunSaveable` are stored; the Stats screen reads and deletes from it). A write never starts from a failed read (it is abandoned, so the history is never erased), keeps the entries it doesn't understand and backs text it can't parse up under `run_history_v1_corrupt`; reads skip entries with an invalid date or route. Each is the only file to change when that data moves to a real database. `planSync.ts` (`loadCurrentPlan`) reads the plan and profile, runs `extendPlan` and saves the result: `usePlanOnboarding` calls it on load and on every Plan focus, and `RunModeScreen` for Today's workout.
- `src/screens/StatsScreen.tsx`: the run history. `runs` is `null` while loading (no empty-state flash), then `StatsContent` fades in once (`useStaggeredEntrance`): Mike's card (`MikeCard`, fed by `statsMikeMessage` in `src/coach/statsMessage.ts`, the one place the next task changes; no message hides the card and its spacing) as the `SectionList` header, then one section per month (`groupRunsByMonth`; month title plus the number of runs and km; sticky headers on white) of `RunHistoryRow`s (memoized, whole-sentence VoiceOver label, hint "Opens the run details"). The list reloads in `useFocusEffect` (Stats is a stack screen, not a tab); only the latest load may change the list (a counter, also bumped by a delete), and `reuseRuns` keeps the objects of runs that didn't change so memoized rows don't re-render. `StatsContent` is memoized, so opening the sheet doesn't re-render the list. Every load parses the whole history: an index without routes (with `getRun` for the detail) is the follow-up if it grows. A row sets `selected` and opens `RunDetailSheet` (`BottomSheet` with its own `ScrollView` capped at 80% of the window and a Done button; route through `RunRouteCard` with the "No route available" copy, three `MetricCard`s, `RunSplits`, `PlanComparisonSection` from the saved planned numbers, and "Delete run"). The map exists only while the sheet is open (the sheet's Modal unmounts its content when closed) and is created about 350 ms after it opens, with a gray placeholder in its place, so creating it can't stall the slide-in and `selected` is cleared in `onClosed`, so the sheet doesn't blank during its exit animation. Delete asks with an `Alert`, calls `deleteRun`, removes the run from the list, closes the sheet and reloads. Empty state: only Mike's bubble ("No runs yet. Ready when you are.", from `statsMikeMessage`) and a "Start a run" button to `RunMode`, centered vertically (the screen scrolls when large text makes them taller; the dev-only "Dev: sample runs" link is small and sits below). `MikeCard` is `MikeAvatar` plus a `ChatBubble`, with no name label; `MetricCard` shrinks its value to fit one line and is one screen-reader element (optional `accessibilityLabel`). Rows and month headers wrap at large text sizes; the empty state scrolls.
- `src/dev`: dev-only helpers, never imported outside `__DEV__`. `sampleRuns.ts` (`seedSampleRuns`, `clearSampleRuns`) saves nine sample runs (ids `dev-sample-run-<n>`, so real runs are never touched; two months, every mode, a plan run, a run without a route and one with two identical points) built from `mockRun.ts`. StatsScreen loads it with `__DEV__ ? require(...) : null`, so Metro drops it from release and preview bundles (checked by exporting a production iOS bundle and searching it for the helper's strings). Use it by long-pressing the "Stats" title (or the "Dev: sample runs" link of the empty state).
- `src/tasks`: background tasks
- `src/utils`: formatting (`format.ts`, including `formatSpokenDuration` for screen readers), calendar dates (`dates.ts`, local `YYYY-MM-DD`; `formatRunRowDate` "Sat, Oct 3 · 7:42 AM" and `formatRunSheetDate` for a run's moment, in the device's local time), location, haptics, the wheel picker's row math (`wheel.ts`: a row is `round(offset / ROW_HEIGHT)`, `nearestRow`, the slow-release rule; pure, used by `WheelPicker`) and mock-data helpers. `mockRun.ts` holds mock finished runs (long, goal, short, no route, plan, partial plan) to preview Run results without running; only the dev helper imports it (a short mock run shows the "Run too short" view if you feed it to Run results).
