# Features

What the app does today and what is still missing. Moved verbatim from CLAUDE.md.

Implemented today: fake auth/sign-in, Home dashboard, Stats, the run mode selector (opened by Start run on Home: Quick start, Set a goal, Intervals and Today's workout; without a workout waiting, or with today's one done, a sheet offers a free run), Intervals (a light setup screen to build your own workout: warm-up, up to four blocks of reps and sets, each with its work by distance or time, zone, rest between reps and sets, quick presets, a live estimate, GPS-rule notes and the last setup remembered; it runs like a plan workout, as a free run that never touches the Plan, and its results show the reps), goal runs (setup screen where any two of distance, time and pace are set and the third is derived, with range limits and valid one-tap fixes; a goal run view with progress bars and silent red off-track alerts; met / missed goals on Run results), GPS run tracking (background location), the Active Run shell (fades to dark while running and back to light while paused) with a view per run mode (basic, goal, and plan workouts run step by step, each by its type: zone chip and target pace on every step, countdown by time or distance with "Rep i of n" / "Set j of m", calm rests with a preview of the next rep and a set summary in macro rests, manual steps with an elapsed timer and a large Done / Ready button, distance as the hero in Z2 sessions, zone and time left with a zone timeline in tempo / progressive sessions, silent pace alerts by zone (Z1-Z2 only when too fast) with quicker timing on short steps, step haptics (rep start, rest start, 3-2-1), whole-workout bar, skip; started from Start workout on the Plan or Today's workout, with edits included; finishing marks the workout completed, or partial when cut short, and stores the actual stats), Run results (distance hero, time / pace / calories, route map or an empty state, per-kilometer splits, a short-run state, goal results, planned vs actual for plan runs, the reps of a structured workout against their targets; sections fade in one after another), the Plan onboarding (Mike's scripted first-visit chat that builds the runner profile, including the plan length: one week at a time or a full month), the Plan screen (Week / Month views of a 4-week monthly plan, or only the week view of a weekly plan, which gets its next week added when that week starts and the app opens; six categories by color: Easy, Aerobic, Tempo, Long, Intervals, Speed; the card shows the session name, e.g. Fartlek or HIIT, its structure in coach notation and its top zone, plus a Zones link to the zone guide sheet; finished days are marked with a check in the workout color, and a finished workout's card shows the actual stats and a "Run again freely" link), structured sessions assigned by the generator (regenerative, extensive aerobic, progressive, tempo run, strides, fartlek, mixed and long intervals, HIIT, HIIT in sets, sprints; zones Z1-Z5 by pace; sets with macro rests; manual Done / Ready steps for what GPS can't measure), the Your profile screen (opened from the gear on the Plan screen: change any onboarding answer, and on leaving, a sheet offers Create a new plan (rebuilds every planned workout from today on, edited ones included; finished and skipped ones stay; a short "building your plan" state of at least 1.2 s, then back to the Plan screen, where Mike announces it; if it fails, an error state with Try again / Not now keeps the old plan) or Keep current plan, shown only when the plan answers differ from the ones the saved plan was built from, and a "Create a new plan" row at the bottom does the same on demand after a confirmation, through the same function and the same loading state; plus the "Intensity by" setting, Pace only, Heart rate coming soon) and the workout editor (opened from Edit on the workout card: a free-scrolling run type carousel with every session (native horizontal scroll that snaps to the centered tile) and a draggable duration bar that follows the finger; saved workouts are marked `edited`).

Run history: a finished run of at least 500 m and 3 minutes of moving time is saved on the device (`runHistoryStorage`); shorter runs are not saved and Run results shows a "Run too short" view (what the minimums are, the distance and time of the run, and one Back to Home button).

Stats screen: Mike's card on top (his line is a placeholder greeting from `statsMikeMessage`; no message, no card), then the run history newest first, grouped by month (month title with the number of runs and the distance of that month), each run a row with its date and time, distance, moving time, average pace and a tag (its planned workout, or Goal run / Intervals; a quick run has none). The history reloads every time the screen gains focus. Tapping a row opens a bottom sheet: route map (or "No route available"), distance / time / pace cards, splits, planned vs actual for a plan run and a "Delete run" action with a confirmation (deleting a run does not undo a finished plan workout). With no runs it is only Mike's bubble ("No runs yet. Ready when you are.") and a "Start a run" button to the run mode selector, centered. In development, long-pressing the "Stats" title adds or removes sample runs (`src/dev/sampleRuns.ts`).

Not implemented yet (Home cards exist as placeholders): AI Coach chat, Routes. Mike has no real content on Stats yet (only the placeholder greeting), Stats has no totals, charts or filters, and a run is lost if the app is killed mid-run. Plans are mock data from `generatePlan`. A monthly plan is not renewed after its four weeks yet, and weekly plans continue the pattern with no adaptation to what was run. The workout editor can't move a workout to another day or add one on a rest day yet, and edits a session only by its total time (editing its reps, sets and zones is a follow-up). The coach's warm-up drill routine (as a text note) is not added yet. Zones are by pace only: there is no heart rate. Nothing consumes the workout events yet (Mike's voice will).
